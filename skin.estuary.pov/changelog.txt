[B]1.3.0[/B]
• The Siri remote fixes have moved out of this skin and into the Apple TV
  Fixes add-on, which is the same add-on that carries the Python repair and is
  in the same repository. If you are on an Apple TV, install it once and both
  fixes are yours whatever skin you use afterwards.
• Apple TV owners already running it: update it to 1.1.0 and the remote keeps
  behaving exactly as it does now. There is nothing else to do.
• Apple TV owners NOT running it: your Siri remote goes back to Kodi's stock
  behaviour when you update this skin. Back stops playback in fullscreen video,
  there is no button that returns to fullscreen, and back at the home screen
  opens the Favourites window. Installing Apple TV Fixes puts all of it right.
• Why it moved: a remote belongs to the box, not to a skin. Written from a skin
  it only worked while you used this skin, an Apple TV owner who changed skin
  lost it with no way to see why, and every other skin copying the idea would
  write the same file. The bindings never named a single skin control; they name
  Kodi's own windows and Kodi's own actions.
• This skin now runs no code of its own on any platform. It has no boot
  service, no scripts directory and no Python, and it no longer declares the
  Python api it needed only for that service.
• Nothing changes on Fire TV, Android, Windows, Linux or macOS, and nothing
  that draws on screen changed at all.

[B]1.2.8[/B]
• The Apple TV Python fix is now a separate add-on that Apple TV users install
  themselves. It is called tvOS Python Fix and it is in the same repository as
  this skin. Install it before this skin, once, and you will not need to think
  about it again.
• 1.2.7 installed it automatically, as a dependency of this skin. That fixed the
  ordering, and it also put an Apple TV workaround on every Fire TV, Android,
  Windows, Linux and macOS box that installed the skin, where it starts, checks
  one condition and does nothing. Under 1% of Kodi installs are Apple TVs.
• If you are already on 1.2.7 and have tvOS Python Fix installed, updating to
  this release LEAVES IT INSTALLED and working. Nothing is removed from your box.
  Kodi only removes orphaned dependencies on an uninstall or when you press the
  button for it yourself, and a service add-on is never classified as orphaned in
  the first place.
• Installing it deliberately is also safer than having the skin pull it in. As a
  sibling dependency its head start over POV was won by declaration order, with a
  measured margin of 7 to 12 ms. Installed on its own, before the skin, there is
  no ordering left to win.
• It also means you can follow that add-on's own advice and delete it once Kodi
  ships an Apple TV build that no longer needs it. While the skin imported it,
  deleting it was not something Kodi would let you do.
• Nothing changes on Fire TV, Android, Windows, Linux or macOS. No skin file
  changed in this release apart from this one and the dependency list.

[B]1.2.7[/B]
• Apple TV only: installing this skin on a brand new box no longer throws an
  error at you. Kodi installs a skin's dependencies before the skin itself, so
  POV was being installed and started before the skin that repaired Apple TV's
  Python was even on the box, and POV failed in front of you. Measured on a real
  box: POV was installed at 07:42:31.754, died at 07:42:32.991, and this skin did
  not reach the disk until 07:42:33.108.
• The repair now ships as its own small add-on, tvOS Python Fix, declared as a
  dependency of this skin so Kodi installs it FIRST. On the bench the shim is on
  disk 5 ms after that add-on lands and several seconds before POV is installed.
• That also means the repair works for every add-on that fetches anything over
  the internet, whether or not this skin is the one you use. Multi Weather and
  EZ Maintenance++ included.
• The order the dependencies are listed in is now load bearing and is pinned by
  a test: the fix add-on first, POV last, so the other dependencies' download
  time separates the two.
• A NEW install now seeds four more settings, under the same one-shot marker
  1.2.5 uses for the main menu, so a box that has already run 1.2.4 or later gets
  none of them and keeps every choice its owner made:
    - "Show media flags" starts OFF (General). The key is hide_mediaflags and it
      is inverted, so SETTING it is what switches the row off.
    - "Choose rating to display for media items" starts on "Rating" rather than
      "None" (General). circle_rating is set and circle_userrating and
      circle_bothrating are deliberately left unset, which is exactly the state
      that setting's own dialog produces for "Rating".
    - "Show media fanart as background" starts OFF (Artwork). no_fanart is
      inverted the same way as hide_mediaflags.
    - The home row size starts at 10 rather than 15. It is seeded from Home
      rather than only repaired in SkinSettings.xml:11, because that repair only
      runs when somebody opens skin settings and a fresh box may never do so. The
      two do not fight: the repair rewrites the value only when it is not one of
      5/10/15/20/25, and 10 is in that set.
• "Number of items to show in home screen lists" is renamed to "Number of media
  items to show in home screen list". The number counts films, episodes, albums
  and channels rather than the menu items beside it.
• There is no 1.2.6. It was built and tested but never published, and the number
  is skipped rather than reused so that no two builds can share a version.
• No change on Fire TV, Android or desktop. The Siri remote keymap is unchanged.

[B]1.2.5[/B]
• A NEW install now starts with five main menu items: Movies, TV shows, TV,
  Add-ons and Weather. Music, Music videos, Radio, Pictures, Videos, Games and
  Favourites start switched off.
• None of those seven are gone. Every one of them is still listed, and switching
  any of them back on is one click, under Settings, Skin Settings, Main menu
  items.
• EXISTING boxes: if yours is updating from 1.2.4 the main menu you arranged is
  left exactly as it is and nothing changes. If yours is updating from 1.2.3 or
  earlier straight to this release, its main menu WILL be set to those same five
  items, because 1.2.4 is the release that marks a box as already arranged and
  yours never ran it. Switch the ones you want back on in Skin Settings.
• The seed runs once per profile and is stamped afterwards, so it can never
  rearrange a menu a second time. The seven Skin.SetBool lines run before the
  stamp on purpose: if a load is cut short part way through, the stamp is not
  written and the whole set is reapplied on the next Home load rather than
  leaving a half applied menu.

[B]1.2.4[/B]
• Skin settings no longer show rows that cannot do anything. Switch a home menu
  item off and its "Edit widgets" and "Default select action" rows disappear
  rather than sitting there greyed out. Movies, TV shows, Music, Music videos,
  TV, Radio and Add-ons all behave this way.
• Turn off "Show media fanart as background" and the three fanart pack pickers
  go with it. Turn off the video OSD autoclose and its seconds row goes too.
• "Choose genre fanart pack" was worse than greyed out. With fanart switched off
  it stayed fully clickable and picking a pack did nothing at all. It now hides
  alongside the other two pickers.
• The virtual keyboard suggests words as you type. Kodi installs the
  AutoCompletion add-on together with the skin, on an update as well as on a
  fresh install, so the suggestion strip above the keyboard is no longer
  permanently empty.
• Groundwork with no visible effect: marks profiles that already run the skin as
  arranged by their owner, so that a later release can lay out a default home
  menu on brand new installs only.

[B]1.2.3[/B]
• "Number of items to show in home screen lists" now applies to every home row.
  The Movies and TV shows poster rows already followed it. The Music, Music
  videos, Add-ons, Games, TV and Radio rows were fixed at 15, and no value of
  the setting could move them.
• The live TV and radio rows that carried no limit at all were rendering their
  whole directory rather than a row. Measured on a Fire TV with the setting at
  5: the TV channel groups row held all 12 groups while the poster rows held 5.
• The random music video artists row was pinned to 10 and now follows the
  setting like the rest.
• The Categories rows stay at 20 on purpose. They are navigation rather than
  content, so shrinking them would remove entries such as Playlists and Add-ons.
• The setting takes effect without restarting Kodi, a few seconds after the row
  is next on screen. The button itself is unchanged: one press cycles 5, 10, 15,
  20, 25, and left and right step and stop at the ends.

[B]1.2.2[/B]
• Apple TV only: writes a stand-in for the _scproxy module Kodi 22's tvOS build
  does not ship. Without it urllib.request cannot be imported, so every add-on
  whose dependencies include script.module.requests dies at startup. Measured on
  atv1: POV, Multi Weather, script.openweathermap.maps and EZ Maintenance++ all
  declare it. The shim goes in that dependency's own lib directory, which Kodi
  already puts on the path of everything that declares it, and is rewritten on
  any start where its contents differ.
• Apple TV only: Siri remote keymap. Back leaves fullscreen video with playback
  continuing, double play/pause returns to it, back at Home no longer opens the
  Favourites browser, and select opens the OSD on live TV.
• No change on Fire TV, Android or desktop: both writes are gated on tvOS.
